# 组委会工作台：功能与布局

这份说明只定功能怎么分、页面怎么排、每一步审核看什么、以及这样排的原因。界面还没有改。认可之后再按这一版做。

组委会现在的页面把入驻代录、按编号打开申请、公示表单、账号绑定、来信和终止查证叠在同一屏。首页轮播、最新动态、参与指南写死在代码里，组委会改不了。学生、导师、组织账号也没有一个可检索的管理处。下面按真实使用把这些补上。

组委会不替导师审设计，不替社区给学生写开发指导，不替组织改主页正文。组织账号的登录邮箱和密码由组委会开通时设定，组织自己不能改、不能删。

## 工作台怎么分

顶上是「组委会」身份，下面八个分区，一次只打开一个。分区和现在组织工作台同一套横向页签，内容铺满宽度。

| 分区 | 日常在这里做什么 |
| --- | --- |
| 待办 | 看件数，点进对应分区 |
| 结项终审 | 读社区报来的结项，通过或退回 |
| 公示 | 编写并发布结项公示、中选公示、一般公告；已发布的可以打开正文 |
| 社区来信 | 点开一个社区来回说 |
| 终止查证 | 看证明，核准或驳回终止合作 |
| 账号 | 查学生、导师、组织账号，停用或在符合条件时删除组织 |
| 站点内容 | 首页轮播上新与下架、最新动态、参与指南 |
| 平台设置 | 学生代码平台的授权配置 |

待办里只出现会逾期的业务：待终审、待公示、未回的社区来信、待查证。站点内容和平台设置不进待办数字。改首页不是「今天必须审完」的队列，和终审放在一起会让人错过该审的材料，也会让改错一张轮播图的操作和核准终止放在同一排按钮上。

左名单、右内容用在终审、公示、来信、查证、账号、动态和指南。左栏约 280 像素，选中项有左边色条。右栏占满剩余宽度。空名单仍保留边框，并写这一栏什么时候会出现内容。

## 待办

四行，每行是数字加去向：

- 待终审：社区已报送、组委会还没有结论。
- 待公示：终审已通过、还没有写进公示页。
- 社区来信：对方有新消息、组委会还没回。
- 待查证：终止申请仍是待查证。

件数为 0 时写「没有」，行仍可点。待办本身没有提交按钮。

## 结项终审

这是组委会在结项链上唯一的审核。顺序固定：学生交结项，导师通过，社区把说明和材料送来，组委会终审，通过的进入待公示，到公示分区才对外。设计审核、中期、导师打回，都不出现在这个名单里。

### 名单

两个筛选：待我终审、已退回。一行是「学生 · 项目 · 社区 · 社区报送时间」。按报送时间从早到晚排。不提供申请编号输入框。组委会面对的是队列，打开谁就审谁。

### 打开一份之后，右边从上到下

1. 抬头：学生姓名、项目名、社区名、当前状态「待组委会终审」。
2. 导师结论：导师通过时写的意见，以及通过时间。没有这段，不能点通过。材料区标出「导师结论未附上」，通过按钮不可用。
3. 社区报送说明：社区在「结项报送」里写的那段话。
4. 学生结项材料：报告、仓库链接、附件。附件在页内打开，沿用学生端那种自定义预览，不用浏览器自带的阅读器。
5. 此前若退回过：最近一次退回原因钉在材料上方，更早的放在「全部记录」。

### 结论

底部一条意见框，两个按钮：通过、退回。

- 通过不必填写意见。通过后这一行离开「待我终审」，出现在公示分区的「待编写」。学生、导师、公开的结项公示页此时都还看不到结果。
- 退回必须写原因。材料回到该社区的「结项报送」，社区改完说明或补材料后可以再交。学生看到的是「待社区重新报送」，不是「结项失败」这种无法再交的结束语。
- 两个按钮都在这份材料的底部，不在左边名单上。没有点开材料就不能通过。

这样排，是为了让通过和公示拆成两步。今天通过、到固定时间再集中发布，公示页不会陆陆续续多出半行。退回写成可再交，社区不用找申请编号重来一遍。

## 公示

公示是对外的正式结果，和「最新动态」分开。动态是近况，公示是审核之后的名单和说明。公开导航里的「结项公示」只显示已发布的公示。组委会在这一分区编写。

### 三种公示

| 类型 | 从哪来 | 公开页上怎么归类 |
| --- | --- | --- |
| 结项公示 | 终审通过后自动出现在「待编写」，一学生一项一条，可在发布前改标题和说明 | 结项公示 |
| 中选公示 | 组委会新建。选择已经入选、尚未结项的学生和项目，写一段说明 | 中选公示 |
| 公告 | 组委会新建。不绑定某一个学生，例如本批公示时间、规则补充 | 公告 |

结项公示不从空白表单起手。终审通过才会产生草稿，避免公示里出现一份没审过的结项，也避免审过了却要再抄一遍学生姓名。

### 编写一份

左边：待编写、已发布。待编写里结项草稿按终审通过时间排列。

右边：

- 标题。结项草稿默认是「项目名 · 学生名」，可改。
- 类型。结项草稿的类型锁定为结项公示。
- 正文。结项草稿先填入社区报送说明，组委会可以改写成对外措辞。
- 关联。结项草稿已经绑着那一次申请，不能改绑到别人。中选公示用多选勾学生。公告没有关联人。
- 发布时间：立即发布，或选一个日期时间。到点之前停在待编写，公开页不出现。

底部按钮是「发布」。发布后学生能在结项公示里看到，本人已结项的会出现在「我结项的项目」。点开标题进入正文，不只在列表里显示一行摘要。

### 已发布之后

已发布按今年、往年两个筛选，和现在公开页一致。点开仍是正文。

撤回不是直接消失。组委会填写撤回原因后，公开页该条保留标题，正文换成「本条公示已撤回」和原因，并记下撤回时间。已经给过结项结论的记录还在，避免别人引用过链接之后变成空白页。撤回后的结项，学生状态不自动改回进行中。若确实审错了，先撤回公示，再在终审「已退回」之外单独说明，由社区重新报送。这一步写在操作说明里，不做成一个隐蔽的「取消完成」按钮。

好处：公示有草稿、定时、正文和撤回记录。公开页点进去能看到组委会真正写过的内容。动态和公示各写各的，近况改错不会改掉结项名单。

## 社区来信

左边是写过信的社区，按最新一条的时间排列。右边只和这一家来回显示。输入框的发送对象写着这个社区的名字。

结项说明不进这里。报送走终审里的材料。没有结项时，社区也可以来问公示日期、账号、规则。

多家同时来信时，回复只进当前这一家。没有来信时左栏仍在，说明组织在「对接组委会」里发送之后会出现。

## 终止查证

只处理进行中的合作。情形限定为：不做、不回复、乱做、辱骂，以及其他写明了的严重问题。已经结项的学生由社区在自己的对接里点「结束对接」，关掉后续通知，不进组委会这一分区。

### 名单

默认「待查证」。可切到「已核准」「已驳回」。一行显示社区、学生、项目、情形、提交时间。

### 打开一份

右边固定为这几段，缺任何一段时核准按钮不可用：

1. 社区、学生、项目、学生当前状态。若学生已经结项，按钮不可用，并写明请社区使用结束对接。
2. 情形。
3. 经过。社区必填，短于说清时间和事情的，在社区侧就提交不了。组委会看到的是原文，不能替社区改写。
4. 证明。每条链接单独一行，可点开。至少一条 http 或 https。图片也以链接形式提交。组委会打不开全部链接时，可以驳回并写「证明无法打开」，不能在一条都没点开的情况下核准。
5. 查证结论。必填。然后核准终止或驳回。

核准后：该学生与这个项目的合作结束，名额按现有「取消接取」的规则释放（状态允许时走这条，不允许时记为已终止并停止继续提交）。学生和该社区管理员都收到结论，正文是组委会写的查证说明，并带上社区名。

驳回后：合作继续。社区看到未通过和原因，可以再交一份新的申请。上一份留在「已驳回」，不覆盖。

名单上不放核准按钮。和终审一样，先打开证明再决定。

## 账号

三个页签：学生、导师、组织。都是搜索姓名或邮箱，点开一个人再操作。不在列表行上放删除。

### 学生

能看到：姓名、邮箱、学校、进行中的申请数、已结项数。

能做的：停用、恢复。停用后不能登录。已经存在的申请、导师审核记录、公示都保留，导师仍能打开这条记录。

不能做的：修改学生自己注册的密码。有过申请记录的学生不能删除，否则公示和审核对不上人。从未提交过申请的学生可以删除，删除前要输入邮箱确认。

于鸿伟这类自行注册的账号同样出现在这里，只是没有组委会设定的初始密码可以重置。

### 导师

能看到：姓名、邮箱、所属社区、负责的项目、名下进行中的学生数。

能做的：停用、恢复。停用后不能登录。

名下还有进行中学生时，停用按钮不可用，并写明先由该组织在工作台把项目改派给别的导师。组委会不在这个页上把学生批量改派，避免改完才发现审核意见还挂在原导师下。

不删除有过审核记录的导师。

### 组织

能看到：组织名、组织管理员邮箱、邀请码是否已发放、项目数、进行中学生数、状态（启用 / 已停用）。

开通在「平台设置」旁边的开通表单里，不在搜索结果里临时造账号。开通时填写组织名称、英文标识、一句简介、管理员姓名和邮箱。系统生成初始密码，只在成功页显示一次，并生成导师邀请码。提示把这两样单独交给组织管理员，不要发到学生能看到的页面。管理员之后不能在组织主页里改邮箱或密码。

停用：组织公开页还在，项目仍可查看，但不能再报名。已接取的学生继续做到结项。停用可恢复。

删除比停用更窄，必须同时满足：

- 已经停用。
- 没有进行中的学生。
- 没有已发布的结项公示挂着这个组织。有公示的组织只能停用，不能删除。
- 组委会输入完整组织名称才能确认。

没有项目、也没有学生的空组织，停用后可以删除。有历史公示的保留，是为了公开页上的名字还能点回组织说明，而不是变成失效链接。

好处：停用是可逆的管理手段，删除只留给确实没有对外记录的空壳。学生和导师的审核痕迹留下来，公示不用改人名。

## 站点内容

三个页签：首页、最新动态、参与指南。修改后访客看到的就是这一份，不再改代码。

### 首页轮播

对应现在首页上那一排大图：标题、导语、角标、两个按钮、左右切换和底部圆点。现状是三张图写在程序里。组委会改为维护一份「展示中」和一份「已下架」。

一张幻灯片的字段：

- 两行标题。
- 导语。
- 角标，例如「活动流程全年可演示」。
- 背景图：上传，或填写图片地址。
- 主按钮、次按钮：按钮文字和站内路径，例如查看项目指向 `/projects`，参与指南指向 `/guide`。

展示中最多 5 张，按组委会排的顺序播放，第一张是首页打开时看到的。超过 5 张时，上新按钮不可用，提示先下架一张。

上新：新建一张，默认排到展示中的第一位，保存后首页立刻能看到。下架：从首页圆点里消失，进入「已下架」，内容和图片还在，可以再上架。不下架成彻底删除，是因为上一期的大图常常还要拿回来，删了就要重新传图。

右边一块预览，比例和首页大图一致，用来看文字会不会压在按钮上。预览不是另开一个「预览站」，首页就是发布之后的效果。

### 最新动态

公开页 `/news` 和导航「最新动态」读的是这里发布的条目，不再是写死的三条。

一条动态的字段：标题、日期、列表摘要、正文。正文可以分段落。可含一个站外链接，例如俱乐部官网。

左边：展示中、已下架。右边：编辑。按钮是「发布」和「下架」。

访客在最新动态里看到的是摘要列表。点标题进入这一条的正文页，能读到组委会编辑的全文，而不是只在卡片上重复摘要。首页轮播上「最新动态」按钮仍进列表。

动态不下到结项公示里。公示有学年和撤回规则，动态没有。把活动新闻写进公示，会让人以为那是审核结论。

### 参与指南

公开页仍然是现在的五本：热点问题、组织指南、学生指南、导师指南、经典流程指南。组委会改的是里面的章节，不改这五本的入口结构。访客按角色找指南的习惯留着。

左边先选一本，再列出这一本的章节。选中一章，右边是标题和正文。可以新增一章、调整顺序、隐藏一章。隐藏的章节访客看不到，组委会还留着，避免误删一整段操作步骤。

保存分两步：「存草稿」只在组委会预览里看见；「发布到参与指南」之后，`/guide` 和首页按钮「参与指南」打开的才是新内容。发布前预览用公开页同一套目录，避免编的时候是一列，发出去又换了结构。

旧章节被新章节替换时，上一版正文留一份「上一发布」，可以整本退回上一发布。单章退回只影响这一章。这样改错导师指南不会把学生指南一起退回去。

## 平台设置

学生代码平台仍用现在的配置页：GitHub、Gitee、GitCode、GitLink、俱乐部 Gitea。工作台这个分区只放一句说明和进入配置的入口，密钥表单不铺在终审下面。

未配置时，学生绑定页提示尚未开通。终审、公示、账号停用不依赖这项配置。

开通组织的表单也放在这个分区的上半：开通是低频动作，和改密钥一样，不应占住待办。开通成功页单独展示初始密码和邀请码，离开页面后密码不再显示。组织管理员忘记密码时，由组委会在账号分区对该组织执行一次「重新发放初始密码」，新密码同样只显示一次，旧密码失效。这是组委会发放，不是组织自己到页面上修改。

## 各审核对照

| 事情 | 谁先做完 | 组委会看到什么 | 通过之后 | 退回之后 |
| --- | --- | --- | --- | --- |
| 设计与中期 | 导师 | 不出现 | — | — |
| 结项终审 | 导师通过，社区已报送 | 导师意见、社区说明、学生附件 | 进入公示「待编写」，尚不公开 | 回到社区结项报送，可再交 |
| 发布公示 | 终审已通过，或组委会写了中选/公告 | 标题、正文、关联的人 | 结项公示页可点开正文 | 发布前可继续改；发布后只能撤回并保留原因 |
| 终止合作 | 社区提交情形、经过、链接 | 原文和可点开的证明 | 合作结束，双方收到结论 | 合作继续，申请留在已驳回 |
| 结束对接 | 学生已结项 | 不出现 | 社区自己关闭后续通知 | — |
| 停用账号或组织 | 组委会在账号里打开这个人 | 进行中的项目数 | 不能登录或不能再报名，记录还在 | 可恢复 |
| 删除组织 | 已停用且无进行中学生、无公示 | 确认用的组织全名 | 空组织删除 | 条件不够则按钮不可用 |

## 这样做的取舍

日常审核和改网站分开，是因为两类操作的对象不同：一份结项材料和一张首页图，误点的后果差很多。放进不同分区之后，待办只催审核和来信。

公示、动态、指南都做成「编辑的正文可以点开」，是因为现在列表上只有一两句，改完也无法从「最新动态」或「结项公示」走到那一篇。访客点标题即正文，组委会才知道自己发出去的是什么。

账号用停用而不是一律删除，是因为审核记录和公示要能对上原来的人。删除只留给没有对外痕迹的空组织、以及从未申请过的学生，并且要用名称或邮箱再确认一次。

先不做的仍然是：组委会不审设计，不在登录页放置组委会入口，不用申请编号当终审入口。登录入口仍是 `/ops/login`。

认可这一版之后再改页面。现有的终审状态、来信、终止申请、结项公示页会接到这些分区上；首页、动态和指南从写死的文案改成组委会发布的内容。
